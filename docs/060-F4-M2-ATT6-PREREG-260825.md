## 1. The question changed, and this document is about the new one

Attempts 1–4 asked *where does the boot stop*.  Attempt 5 answered a different question by accident:
three boots of one artifact, from one byte-identical disk, with the firmware, preset and clocks
gated and read back on every boot, produced **three different stops** — a live stall, a
`swapadd` EINVAL panic, and a signal storm ending in four `ucontext` refusals — and a fourth run did
not boot at all.  The pre-registered wall did not appear once.

So the round-6 question is **"what varies between two identical boots"**, and there are only two
kinds of answer:

* **software nondeterminism** — instructions ran in a different order (interrupt arrival phase, disk
  completion timing, scheduler order, carried state across a warm reset); or
* **a value changed where no instruction wrote it** — the coherency/DMA class this campaign is
  already in, or electrical/timing marginality underneath it.

Those two are separable by measurement, and §5 says exactly how, exactly how far, and — the part
that matters most — exactly where the separation stops.

## 2. What is already settled, statically, before this round starts

All four are derived in `docs/060-F4-M2-ATT5-RESULTS-260825.md` §7 from the booted artifact's own
disassembly and relocation table.  They are restated here as the premises the instruments are built
on, because an instrument built on a wrong premise measures nothing.

### 2.1 `nullvect` is the universal trap stub, and there is an invariant

`_start` sets `VBR = &M68Kvec` and `M68Kvec` has exactly one reference in the image — that one.
**237 of the 256 entries point at `nullvect`**, including vector 2 (access fault) and vector 32
(TRAP #0).  `nullvect_orig` is not a SIGSYS catch-all: it saves `d0-fp`, restores `sup_cacr`, and
branches on the saved SR's S bit to `ktraps` (`jsr k_trap`) or `utraps` (`jsr srg_utraps → u_trap`).
`u_trap`, `srg_utraps` and `k_trap` have **exactly one reference each**.  Therefore

> `M68Kvec[v] → nullvect (the kvp wrapper) → nullvect_orig → utraps → srg_utraps → u_trap`
> is the only route to `u_trap`, the wrapper increments `kvp_n` **before** jumping on, and so
> **`kvp_n ≥ srg_ut_n` holds at every instant whenever `kvp_on ≠ 0`.**

Attempt 5 boot 1 measured `kvp_on = 1`, `kvp_n = 3` at 12:58:02 against `srg_ut_n = 360` read
**five seconds earlier**, rising to 1270.  **The invariant is violated by at least 357, and by at
least 1267 by the end of the window.**  Three mechanisms survive; §4's Table K decides between them.

### 2.2 `kvp_super_n` is structurally dead

`src/kvecprobe040.s` loads the saved SR into `%d1` and does `btst #5,%d1` — the **register** form,
which is a long operand with the bit number mod 32, so it tests SR bit 5 (an always-zero bit) rather
than S = bit 13.  Measured from the linked image at `0xda95a`: `0801 0005`.  The branch is never
taken; **every** entry lands in `kvp_user_n`.  Attempt 5's "all user" was never a measurement.

Not fixed this round: `kvecprobe040.o` is in the **base** link, so correcting it changes every
artifact the 030 and 040 arms are compared against.  Round 6's own instrument reads the S bit with
the memory form on the SR's high byte, which is what `nullvect_orig` itself does.

### 2.3 `src/srgtrap.s`'s ring reads the wrong offsets, and this round must not inherit them

`nullvect_orig` pushes **60 bytes** (`moveml %d0-%fp,%sp@-`, mask `0xfffe`; its own
`btst #5,%sp@(60)` confirms the count) before `utraps` pushes the USP and the `jsr` pushes the return
address.  So at `srg_utraps` entry:

```text
  %sp+0    jsr return address (0x11f4)
  %sp+4    the USP utraps pushed
  %sp+8 .. %sp+67    nullvect_orig's 60 saved registers, d0-d7 then a0-a6
  %sp+68   frame SR (word)
  %sp+70   frame PC (long)
  %sp+74   frame format/vector (word)
```

`srgtrap.s:98-102` documents the frame words 60 bytes lower, so `srt_vec`, `srt_pc` and `srt_d0` do
not hold what their names say.  No result in this campaign rests on them — the ring was never
reported in attempts 3, 4 or 5 — and they are not fixed here, for the same base-change reason.
**Round 6's instrument uses the offsets above and carries three self-checks that fail loudly if they
are wrong** (§3.1).

### 2.4 The printed `ucontext` checksum is the **second** of two folds

`restorecontext` (`0x058d76`) folds 201 longwords at `ucp+0xD8` and compares against `0xFFFFFFFF`
— *that* fold decides.  On failure it folds **the same 804 bytes again** and prints **that** value.
So all five samples in the `0xFFFFEFFF` / `0xFFFFDFFF` / `0xFFFFCFFF` family are readings of a
re-read, and **fold #1 has never been seen by anyone**.  `savecontext` (`0x058f10`) folds 200 over
`[ucp+0xD8, ucp+0x3F8)` and stores `~sum` at `ucp+0x3F8`; `stampsum` (`0x059538`) is a plain XOR
fold.  `mc_state` therefore begins at **`ucp+0xD8`**, which is where `prgetstate`/`prsetstate` are
handed the pointer, so `mc_state[0..3]` is `ucp+0xD8 .. ucp+0xE4`.

**Both `ucp` values are kernel addresses.**  `setcontext` does `linkw %fp,#-1024` and passes
`%fp-1024` to `savecontext` and, after a `copyin`, to `restorecontext`; `sendsig` does
`linkw %fp,#-1192` and passes `%fp-1024` to `savecontext` before `copyout`ing it.  A probe on either
reads kernel memory only — the same rule `src/ufault_dbg.s` was built under.  `savecontext` has two
callers (`setcontext+0x3e`, `sendsig+0x15a`); `restorecontext` has one (`setcontext+0x9c`).

### 2.5 DTT0 makes the whole kernel image non-cacheable for data, and that re-scopes two rows

**Added 2026-08-25, after §1–§2.4 and §3–§10 were committed and still before a line of instrument
code was written.**  The correction is a static fact about the artifact, not a reading; the commit
order in this repository is the audit trail, and nothing that follows a boot is ever adjusted this
way.

`src/pstart040.s:326-327` loads `DTT0 = 0x003FC060`: logical base `0x00`, mask `0x3F`, E=1,
**CM=11 cache-inhibited**, matching logical `0x00000000`–`0x3FFFFFFF`.  The kernel is loaded at
`0x08000000`, which matches.  So **every data access to the kernel's own `.text` and `.data` —
`M68Kvec`, `swapfile`, and every counter block this campaign has ever read — bypasses the data
cache entirely.**  The value is confirmed live: attempt 5 read `z3660_dtt0 = 003FC060` on all three
boots, and `pstart040.s`'s own B1 note says so in as many words ("the low identity window keeps
direct phys/page-table/MMIO access NC").

The kernel **stack** is elsewhere.  `iur_a7 = 0x40001FB8` matches neither DTT0 (`0x40 & 0xC0 = 0x40
≠ 0x00`) nor DTT1 (`0x40 & 0x80 = 0x00 ≠ 0x80`), so it is PTE-mapped and takes its CM from the leaf
descriptor — `hat_cm_ram = 0x00`, **writethrough**.  That is where the `ucontext` buffer lives.

Three consequences:

* **`kvd_a_e2c` / `kvd_a_e32c` are not a coherency test and are not registered as one.**  A
  `cinvl dc` before a cache-inhibited read cannot change the answer.  They are re-registered as a
  **check of the DTT0 premise itself**: a difference means DTT0 is not doing what `pstart040.s` says,
  which is a finding about the MMU setup and not about DMA.  Table K's K4 row is re-worded below.
* **`kvd_n` versus `kvfar_n` gets sharper, not weaker.**  Both live in the low window, so both stores
  are cache-inhibited and go to the bus.  A divergence between two adjacent stores to two
  cache-inhibited addresses cannot be a stale line, a lost writeback or an eviction — it is a **bus
  or DRAM** event.  The same now goes for Table M's `.data` integrity row: a static longword in the
  low window that reads back wrong was read from RAM, not from a cache.
* **`mcs`'s two cache rows keep their meaning and split cleanly**, because the `ucontext` buffer is
  on the writethrough-cached kernel stack.  `fold_a` vs `fold_b` tests stability across two reads
  that may both hit the same cache lines; `fold_b` vs `fold_c` tests whether those lines agree with
  RAM.  Under writethrough there are no dirty lines, so the `cpushl dc` acts as an invalidate and the
  third fold is forced from RAM.

**Table K row K4, replacing the row printed in §4:** `kvd_a_e2c != kvd_a_e2` or
`kvd_a_e32c != kvd_a_e32` → *the DTT0 premise is wrong: a `cinvl dc` changed the value read from a
region this kernel maps cache-inhibited.*  Report it before any other row, and treat §2.5's other
two consequences as unsupported until it is explained.

**§5.1, amended:** the row "`kvd_a_e2c != kvd_a_e2` … on a `.text` line that nothing ever writes" is
withdrawn as a software-cannot-produce-this signature and replaced by the premise check above.  The
`kvd_n != kvfar_n` row is strengthened: with both addresses cache-inhibited, no cache mechanism of
any kind can produce that divergence.

## 3. The instruments

Three new units, four hook points, all read-only, none of which dereferences a user address.

| unit | block | hook | how it is bound |
|---|---|---|---|

**Deliberately NOT hooked: `nullvect` itself.**  Chaining in front of the vector table's own entry
point is the highest-blast-radius hook available — a bug there is a kernel that never boots and a
15-minute window spent on nothing.  Everything §2.1's contradiction needs is visible one step
further in, at `srg_utraps`, **which is the side of the contradiction that ran 1270 times**.

`src/ufault_dbg.s` rides again, unchanged, from `relink-040-f4arms.sh --ufault`.  Attempt 5 proved it
inert on the bench and inert on three metal boots.  The wall is now known to be a low-probability
draw, so the right thing to do with a proven, inert census is to **carry it on every boot until it
catches one**.

### 3.1 Self-checks that must pass before any value in a block is believed

Each is a longword in the block, not a comment.  If one fails, that block's readings are **void, not
negative** — the same rule §3.1 of the attempt-5 pre-registration used.

**`kvd`:**

* `kvd_f_sr & 0x2000 == 0`.  `utraps` is the **user** arm by construction, so the saved SR's S bit
  must be clear.  If it is set, §2.3's offsets are wrong and every frame field below is noise.
* `kvd_f_usp == kvd_f_nowusp`.  The USP `utraps` pushed at `%sp+4` must equal `%usp` read now;
  nothing between them touches it.  A second, independent proof of the same offsets.
* `kvd_f_vbr == kvd_f_tabaddr`.  VBR must equal `&M68Kvec`.  If it does not, the CPU is dispatching
  through a table the kernel does not maintain, and **that is a larger finding than anything else in
  this document** — stop and report.

**`mcs`:**

* `mcs_s_bad_n == 0`.  Our own 201-longword fold, taken **immediately after `savecontext` returns**,
  must read `0xFFFFFFFF`.  If it does not, the stamp is wrong at birth and every `restorecontext`
  reading is about a frame that was never valid.
* `mcs_r_n > 0` before any `mcs_b_*` slot is read.  A `mcs_stamp` still 0 while `mcs_r_bad_n > 0`
  means the first-bad body did not run and the whole `mcs_b_*` block is void, not negative.

**`swa`:**

* `swa_n == 1`.  `swapconf` is called once from `main+0x154`; more than one call means the retarget
  caught a site this was not measured on.
* `swa_lowblk == 0x00000000`, `swa_nblks == 0x0000F000`, and `swa_name == &swapfile + 0x10`.  All
  three are **static `.data` longwords in the image**, read out of the artifact before the boot
  (§6).  A runtime disagreement is a `.data` integrity failure and is a bigger finding than the stop
  (§4, Table M row 5).

### 3.2 Block layouts, registered

Every slot is a longword.  **Everything is hex.**  A slot reading `ffffffff` means *not applicable*,
not zero.  Every runtime address comes from `tools/status-facts.sh` against the artifact that will
actually be booted, at the load base actually observed — never from an on-box `nlist`, because the
kernel under test is installed into the **boot slice** and `/stand/unix` is a different kernel.

**`kvd` — the vector-dispatch census.  One `kpeek` reads the whole block, in this order:**

```text
  kvd_magic       "KVD!"
  kvd_on          1 = census in the path; 0 takes it out
  kvd_n           entries to this edge  -- the twin of srg_ut_n, one step further in
  kvd_split_n     audits at which kvd_n != kvfar_n
  kvd_split_first kvd_n at the first split, else ffffffff
  kvd_aud_n       audits performed
  kvd_stamp       "AUD!" once the first audit ran

  -- the FIRST entry, latched once
  kvd_f_sr        frame SR word          (self-check: S bit clear)
  kvd_f_pc        frame PC
  kvd_f_fv        frame format/vector word
  kvd_f_vec       (fv & 0x0fff) >> 2  -- the arriving vector NUMBER
  kvd_f_usp       the USP utraps pushed  (self-check against the next slot)
  kvd_f_nowusp    %usp read now
  kvd_f_vbr       VBR                    (self-check against the next slot)
  kvd_f_tabaddr   &M68Kvec
  kvd_f_nullvect  &nullvect -- what a table entry SHOULD read
  kvd_f_e_vec     M68Kvec[kvd_f_vec] as read
  kvd_f_e_vec_c   the same entry after `cinvl dc` on its line -- cache vs RAM

  -- the LAST entry, rewritten every time
  kvd_l_vec  kvd_l_pc  kvd_l_fv  kvd_l_sr

  -- the AUDIT, rewritten every 256th entry and forced on any split
  kvd_a_at        kvd_n at the last audit -- says how fresh the rest of this block is
  kvd_a_vbr       VBR
  kvd_a_e2        M68Kvec[2]   (access fault)
  kvd_a_e2c       the same after `cinvl dc`
  kvd_a_e32       M68Kvec[32]  (TRAP #0, the syscall gate)
  kvd_a_e32c      the same after `cinvl dc`
  kvd_a_e11       M68Kvec[11]  (fpsp_vec11 -- a NON-nullvect control entry)
  kvd_a_nvcnt     how many of the 256 entries equal &nullvect   -- static value 237
  kvd_a_sum       XOR fold of all 256 entries
  kvd_a_sum0      the same fold at the FIRST audit
  kvd_a_chg_n     audits whose fold != kvd_a_sum0
  kvd_a_i         index of the first entry differing from the first-audit snapshot
  kvd_a_was       its snapshot value
  kvd_a_now       its value now
  kvd_a_kvpn      kvp_n     sampled in the same breath
  kvd_a_kvpon     kvp_on    sampled in the same breath
  kvd_a_srgn      srg_ut_n  sampled in the same breath
  kvd_snap        1024 bytes: the whole table as it read at the first audit
```

`kvd_a_kvpn` / `kvd_a_srgn` exist so that §2.1's two counters are sampled **by one instruction
stream at one instant**, rather than by two console reads five seconds apart.

**`kvfar` — the same increment, deliberately far away:**

```text
  kvfar_magic     "KVF!"
  kvfar_n         incremented by the instruction immediately after kvd_n's increment
```

`kvfar_n` is placed **at least 8 KiB after** `kvd_snap` in `.data`, so the two counters are
guaranteed to sit in different 4 KiB pages.  Nothing in software can make one of two adjacent stores
land and the other not.  This is the control for §2.1's mechanism 2, and §5 leans on it.

**`mcs` — the `ucontext` stamp latch.  One `kpeek`:**

```text
  mcs_magic       "MCS!"
  mcs_on          1
  mcs_s_n         savecontext calls
  mcs_s_bad_n     savecontext calls whose 201-fold != FFFFFFFF right after it returned (self-check)
  mcs_r_n         restorecontext calls
  mcs_r_bad_n     restorecontext calls whose 201-fold != FFFFFFFF at entry
  mcs_r_unstb_n   restorecontext calls where two back-to-back folds DISAGREED
  mcs_stamp       "MCF!" once the first-bad body ran

  -- the LAST savecontext, rewritten every call
  mcs_s_ucp  mcs_s_ret  mcs_s_stamp  mcs_s_fold
  mcs_s_ms0  mcs_s_ms1  mcs_s_ms2  mcs_s_ms3        -- mc_state[0..3] as stamped

  -- the FIRST BAD restorecontext, latched once
  mcs_b_seq       mcs_r_n at the moment
  mcs_b_ucp
  mcs_b_fold_a    our 201-fold, read 1
  mcs_b_fold_b    our 201-fold, read 2 -- back to back, no store between
  mcs_b_fold_c    our 201-fold, read 3 -- after `cpushl dc` over all 51 lines of the region
  mcs_b_stamp     ucp+0x3F8
  mcs_b_ms0..ms3  mc_state[0..3]
  mcs_b_blk0..blk7  eight per-block folds of the 201 longwords (25 x 7 + 26)

  -- the LAST GOOD restorecontext, rewritten every time
  mcs_g_ucp  mcs_g_stamp  mcs_g_ms0..ms3  mcs_g_blk0..blk7
```

**`swa` — the `swapadd` operand latch.  One `kpeek`, and it fires on EVERY boot:**

```text
  swa_magic      "SWA!"
  swa_n          calls -- must be 1
  swa_vp         arg1 = swapfile.bo_vp, the vnode lookupname filled in
  swa_lowblk     arg2 = swapfile.bo_offset   -- static, must read 00000000
  swa_nblks      arg3 = swapfile.bo_size     -- static, must read 0000F000
  swa_name       arg4 = &swapfile.bo_name    -- static, must read &swapfile+0x10
  swa_si_pre     swapinfo   before the call
  swa_nsf_pre    nswapfiles before the call
  swa_ret        d0 after   -- 00000000 = success, 00000016 = EINVAL
  swa_si_post    swapinfo   after
  swa_nsf_post   nswapfiles after
  swa_si_start   *(swapinfo+8)   after, if swapinfo != 0 -- the area's start BYTE offset
  swa_si_npgs    *(swapinfo+40)  after, if swapinfo != 0 -- its length in 4 KiB pages
  swa_si_flags   *(swapinfo+36)  after, if swapinfo != 0
  swa_stamp      "SWB!" once the post-call body ran
```

#### 4.1 The three readings of "bits 12 and 13", and what kills each

Five samples, all confined to bits 12 and 13, flipping independently.  Three readings fit the
arithmetic and this document registers what separates them **before** the measurement:

| reading | what it predicts | what confirms it | what kills it |
|---|---|---|---|
| **format nibble** — the longword's low half is an exception-frame format/vector word, `0x4008` becoming `0x5008` / `0x6008` / `0x7008` | the low twelve bits (`0x008`, the vector offset) never move, and bits 14–15 never move | an `mcs_*_msN` whose low half reads `0x4008` in the good latch and `0x5008`/`0x6008`/`0x7008` in the bad one | any sample where bits 0–11 or 14–15 also differ; or a delta in a longword that is not a frame word |
| **SR contamination** — the longword's low half is a saved SR, and S (bit 13) / M (bit 12) are being set or cleared | the delta appears in a slot that holds an SR, and the affected values are plausible SRs | an `mcs_*_msN` whose low half reads like an SR (`0x0000`, `0x2000`, `0x2700`) on one side and differs only in S/M | the same slot reading `0x4008` — a format word is not an SR; or the delta landing in `mc_state[77..199]`, which holds no SR |
| **bit-position / electrical** — bits 12 and 13 are two **data-bus lines**, and the corruption is indifferent to what the longword means | the affected longwords have **unrelated content** across samples, and the same two bit positions recur anyway | the delta appearing in different `blkN` on different samples, or in `mc_state[77..199]` garbage, while still confined to bits 12–13 | every sample landing in the same semantically-meaningful slot with semantically-legal results |
| **summation artifact** — nothing changed and the two folds cover different things | — | — | **already killed, before the boot**: our fold uses the same algorithm over the same 201 longwords from the same base, and `mcs_s_bad_n` proves the stamp is self-consistent at birth.  Registered as dead so it cannot be revived after a reading |

#### 4.2 A standing finding this round does not act on

## 5. The class discriminator: software nondeterminism vs electrical marginality

Registered explicitly, because the honest answer has three parts and only the first is comfortable.

### 5.1 What these instruments CAN separate

Each row is a signature that **no ordering of instructions can produce**.  A hit on any of them means
a value changed where no instruction wrote it.

| signature | why software cannot produce it |
|---|---|
| `kvd_n != kvfar_n` | the two are incremented by adjacent instructions in one uninterruptible sequence, into `.data` longwords ≥ 8 KiB apart.  No scheduling order makes one store land and the other not |
| `mcs_b_fold_a != mcs_b_fold_b` | two folds of the same 804 bytes with no intervening store.  The buffer is a kernel stack frame belonging to the running thread; nothing else has a pointer to it |
| `mcs_b_fold_c != mcs_b_fold_b` | the only difference is a `cpushl dc` over the region.  A different answer means the cache and RAM held different bytes |
| `kvd_a_e2c != kvd_a_e2`, `kvd_a_e32c != kvd_a_e32` | the same, on a `.text` line that nothing in the image ever writes |
| `kvd_a_chg_n > 0` with `kvd_a_i`/`was`/`now` | a `.text` longword changed value between two reads, in a table with exactly one reference in the whole image |
| `swa_lowblk`/`swa_nblks`/`swa_name` disagreeing with their file constants | three static `.data` longwords read back differently than they were built |

**But that cut is "a value changed where nothing wrote it" versus "instructions ran in a different
order".  It is NOT the software-versus-electrical cut**, and this document refuses to let it be read
as one: a DMA engine writing the wrong physical address produces every signature above and is a
firmware bug, not a marginality.  §5.1 narrows the search; it does not close it.

### 5.2 What these instruments CANNOT separate, stated plainly

* **Interrupt-arrival timing races versus silicon marginality as the ROOT of the divergence.**  Every
  instrument above reports a symptom at a place.  If none of §5.1's signatures fires — every fold
  agrees, both twin counters agree, every static operand reads its file value — the divergence is
  equally consistent with ordinary software nondeterminism *and* with a marginality these probes
  happen not to cover.  **A null result on all of §5.1 is not evidence for software.**  It will not
  be reported as one.
* **Where the varying `swapadd` operand comes from.**  Table M measures `va_size`; it does not say
  whether the wrong value came from the disk, from the driver, from a stale cache line, or from a
  `VOP_GETATTR` path that never had the right answer.  M1 is a number, not a mechanism.
* **Any single-boot instrument can measure a draw.  None can measure a distribution.**  Three boots
  gave three outcomes; that is exactly the sample size at which nothing can be concluded about
  proportions, and four will not fix it either.

### 5.3 What session design WOULD separate them — design only, deliberately not scheduled

Registered so that the absence of these from §7's boot plan is not read as an oversight, and so that
nobody re-derives them next round.

1. **N-boot outcome distribution.**  ≥ 10 boots of one artifact from one gated disk, scoring only the
   outcome class and the anchor counters — nothing else, so a boot costs minutes rather than a
   window.  A software race gives a small discrete outcome set whose proportions are stable across
   sessions; marginality gives proportions that move with a physical parameter, plus a tail of
   one-off outcomes.  **This is the prerequisite for every other experiment on this list**, because
   each of them is a comparison of two distributions.
2. **Clock sweep.**  The N-boot protocol at the standing PCLK 50 and at one step down.  If the
   outcome distribution shifts monotonically with clock, the cause is timing-marginal; if it does not
   move across a meaningful range, the CPU/bus clock domain is disfavoured.  The highest-information
   experiment available, and it costs boots rather than code.
3. **The `default_timings` family.**  This campaign has already found one timings-table bug, and
   `default_timings.txt` is a card-side file that attempt 5 fetched (from the wrong path first).  An
   A/B of the standing table against a conservatively de-rated one, N-boot protocol on each arm,
   tests the DRAM-timing arm of the electrical hypothesis directly.  **Card-side change: a user gate,
   not an agent decision.**
4. **Cold versus warm.**  Every boot in attempts 3, 4 and 5 followed an `Escape`/reset rather than a
   power cycle, so DRAM contents and card state carry across.  Splitting the N-boot protocol into
   cold-power-cycle and warm-reset arms tests whether the divergence source is **carried state** at
   all.  The cheapest of the four — it needs no code and no card change.
5. **A resident memory canary.**  A kernel-resident block written once with a known pattern and
   re-verified periodically, in **both** a cached and a cache-inhibited mapping.  Bit flips in a
   region nothing writes are the cleanest electrical signature there is, and the cached/uncached pair
   separates "the RAM changed" from "the cache lied".  **Not built this round**: it wants a periodic
   driver (a clock-tick hook), which is a base change, and this round already carries three new
   hooks over a base that must stay comparable.

## 7. The boot plan, and why it is this order

1. **`unix-060-f6vsm-CARD1-ced0s1`, boot 1.**  Read `swa` **first** — it is the only block guaranteed
   to have fired, it takes one `kpeek`, and on a boot that panics in `swapconf` it is the entire
   reading.  Then `kvd`, then `mcs`, then the inherited blocks.
2. **The same artifact, boot 2, from a fresh gated copy.**  The registered question is no longer
   "does the fault reproduce to the digit" — attempt 5 settled that it does not.  It is **which
   outcome class this draw lands in**, plus Tables K, L, M and N on whatever it produces.
3. **The same artifact, boot 3.**  Three scored boots is the minimum at which "three outcomes" and
   "a distribution" are even distinguishable in principle, and attempt 5 has already shown that two
   boots can disagree completely.
4. **Boot 4 if a window remains.**  Every boot is scored.  **No boot is re-run to green.**  A
   mechanical non-boot is discarded under attempt 5's own rule and only with the same three
   independent proofs (no `Found no handler` lines, no `[PSTAT]` lines, device CRC unchanged).

**Registered as deliberately NOT in the plan, with reasons:**

* **no `--cache 0` control.**  The A/B is settled and a control would stop at `swapconf`'s lookup,
  answering a question nobody is asking and spending a thermal window on it;
* **no `--dbg` combination.**  The `swapconf` probe shifts every counter address again and adds a
  second variable to a boot whose anchor is one counter block — and `swa` now measures the same
  region of the boot with a fraction of the code;
* **no `nullvect` chain.**  §3 says why: it is the one hook whose failure costs the whole window;
* **the fallback artifact is not booted unless the primary produces two mechanical non-boots.**  It
  exists so that a bad round-6 hook does not cost the session its anchor reading, not as an arm.

**Registered risk, and it is not small.**  `mcs` folds 201 longwords on **every** `savecontext` and
every `restorecontext`.  Attempt 5 boot 3b delivered 14,093 signals, so this arm changes the timing
of the signal path measurably.  **A boot in which the `ucontext` refusal does not occur therefore
cannot be read as "the defect went away"** — it is one draw, from a distribution this round has
perturbed.  `mcs_on` exists as a `.data` gate so a control can be stamped one word apart if that
question ever needs answering.
