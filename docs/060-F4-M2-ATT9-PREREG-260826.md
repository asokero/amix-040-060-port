## 2. Two facts round 9 is built on

Both are established readings, not new premises, and an instrument built on a wrong premise
measures nothing.

* **The stable identity of a round-tripped frame is its written region.**  `savecontext` writes
  `mc_state[0..3]` for a format-4 access-error frame (16 bytes: SR/PC, the format-vector longword,
  the fault address, FSLW — `…ATT7-RESULTS…` §7.2).  Every flip this campaign has scored is in
  `mc_state[4..199]`, the *unwritten* field; `mc_state[0..3]` has never been seen to change across
  the round trip.  So `mc_state[0..3]` is a **durable content key** that survives `copyout →
  copyin` intact and can pair a save with its own restore where the colliding stamp could not.
  (An event that flips `mc_state[0..3]` itself would show as a key miss with a bad fold — a
  distinct, interesting signal round 9 counts rather than drops.)

* **The transit points are named kernel paths, already disassembled.**  `…ATT7-RESULTS…` §4:
  `sendsig` calls `savecontext(K_send)` then `copyout(K_send, U, 1024)`; `setcontext` arm 1 calls
  `copyin(U, K_set, 1024)` then `restorecontext(K_set)`.  `K_send` and `K_set` are different kernel
  buffers; **`U`, the user destination, is the one address common to both ends** and is visible in
  `sendsig` and `setcontext` but not in `savecontext`/`restorecontext`.  That is why the multi-point
  arm hooks the former pair and the content-freeze arm the latter.

## 4. The instruments

Two arms, mutually exclusive, each a whole `savecontext`/`restorecontext` (or `sendsig`/`setcontext`)
implementation, plus one optional third arm.  Built over the **same pinned base** attempt 8 used —
`build/unix-040-f7vs`, sha256 `d43a59cc…`, the kvd+swa base with no `ucp`/`ucp2`/`ucz`/`mcs` — so
each build carries exactly one change and §9's determinism proof measures precisely it.

### 4.1 Arm I — `ucv`: content-keyed durable freeze (the pairing fix, cheapest)

Lives in the same two hook points as round 8 (`savecontext` WRAPPED, `restorecontext` PROLOGUE),
adds no new hook site, and **replaces the stamp-keyed 4-slot ring with a deep, content-keyed
save-side store**:

1. **The key is `hash(mc_state[0..3])`** — a cheap fold of the four written longwords (e.g.
   `k = m0 ^ rol(m1,8) ^ rol(m2,16) ^ rol(m3,24)`), computed at both save and restore.  Because
   `mc_state[0..3]` survives the round trip (§2), a save and its own restore compute the same key.
2. **The store is deep enough to retain the failing frame's save-side, and no deeper — because a
   large `.data` addition perturbs the very memory map under test.**  Two tiers, so the footprint
   stays modest:
   * a **deep, fold-only index** keyed by `hash(mc_state[0..3])` — key + save-time plain+rotating
     folds only, ~16 bytes/slot — that reliably **detects** at restore that a paired save's fold
     disagrees.  Cheap enough to be deep (e.g. 1024 slots ≈ 16 KB);
   * a **bounded full-content ring** of the **most recent N save-side frames** (key + 804 bytes),
     from which the failing frame's true save-side is **recovered** when the fold index flags a
     mismatch.  The registered starting `N` is **64** (≈ 53 KB); `ucv_full_n` counts a mismatch
     whose content had already rolled out of the ring, so an insufficient `N` is a **measured
     fact, not a silent loss**, and the next round raises it.
   Keeping the content ring bounded is deliberate: the corruption is memory-map-dependent
   (`…PLATFORM-LC060-Z3660…` §2.6), so the instrument must not move the map more than round 8's arm
   already did without a reason — detection wants depth, content recovery does not.
3. **At restore, look up the key.**  On a hit whose plain fold disagrees, **freeze the true paired
   save-side and restore-side of the failing frame** in a one-shot evidence pair (`ucvev_s` /
   `ucvev_r`, 804 bytes each) together with the per-longword diff.  Verify `mc_state[0..3]` equal
   between the two sides (`ucv_keyok_n` / `ucv_keybad_n`): a key match with unequal `[0..3]` means
   a collision, and it is counted, never assumed away.
4. **The value/address discriminator, computed in-kernel over the frozen pair** (`ucv_va`): for the
   flipping value V, count copies of V in the *save-side* frame and how many of them flipped.  All
   copies flipped → **value-keyed** (R1); exactly the flipped longwords held V → **address-keyed**
   (R2); some but not all → **neither** (R3).  This is what attempt 8 could only do inferentially
   on a restore-side-only frame; over a **measured** save-side it is decisive.

Everything else of round 8's inertness set carries over: the §4.1 sentinel killer (`ucp_sent0` at
logical 0 through DTT0), the VOID self-check, the plain+rotating folds (kept — R1's even-parity
result must remain live), and the whole `swa`/`uft`/`kvd`/`zc` self-check block.

### 4.2 Arm II — `ucm`: the multi-point read (the localizer)

Hooks `sendsig` (after its `copyout`) and `setcontext` arm 1 (around its `copyin`) — **a new hook
site, and the registered cost of this arm** — keyed on the durable user address `U`:

```text
  sendsig, after copyout(K_send, U, 1024):
     A = fold(K_send)                 <- kernel save buffer (already the round-8 save fold)
     B = fold_user(U)                 <- read the user bytes back, fault-safe; the copyout landing
     record (U, A, B) in a U-keyed table (256 slots)

  setcontext arm 1, around copyin(U, K_set, 1024):
     B' = fold_user(U)   (before)     <- the user bytes just before they are read back in
     C  = fold(K_set)    (after)      <- kernel restore buffer (already the round-8 restore fold)
     look up U:  now hold A, B, B', C
     if C != A:  a flip happened -> FREEZE the chain and localize:
        A==B  ? copyout clean : the flip is in the COPYOUT transit
        B==B' ? user DRAM rest clean : the flip is in the USER-MEMORY DWELL (storage)
        B'==C ? copyin clean : the flip is in the COPYIN transit
```

Counters `ucm_copyout_n` / `ucm_dwell_n` / `ucm_copyin_n` / `ucm_none_n` tally which segment each
detected flip localizes to; the first event of each class freezes the full four-point folds plus
the 804-byte content at the two endpoints and the per-longword diff.  `ucm_none_n > 0` — a fold
that fails with A, B, B', C all equal — is the reading that would send the residue back to
software, and it is a registered, first-class outcome.

**User-memory reads are fault-safe.**  `fold_user(U)` runs in the faulting process's own context
(both hooks do), and reads `U` through the kernel's existing fault-safe user-access path so a bad
`U` declines and is counted (`ucm_uaccess_bad_n`) rather than faulting the kernel.  It never
writes user memory and never changes the bytes stock copies.

### 4.3 Arm III — `ucc`: the resident memory canary *(optional; needs a base change)*

The strongest cheap **electrical** decider, registered so the session can pull it forward or
defer it as attempt 6 §5.3 deferred it.  A kernel-resident block written **once** early in boot
with a known pattern and re-verified on a clock-tick hook, held in **both** a cached and a
cache-inhibited mapping.  Counters `ucc_cached_flip_n` / `ucc_uncached_flip_n` and a one-shot
freeze of the first flipped longword (address, expected, observed, XOR).  Its cost is the periodic
hook — a clock-tick driver, a base change — which is why it is optional; if built it is its own
stage over the same base, never folded into Arm I or II.

### 4.4 The owed R9/R10 fix

Round 9 either widens the wall freeze key to the access-error/bus-error vector so `ucv_r_at_wall`
can latch on the `4AFC0008` path (one added hook read), or, if that is judged too invasive for the
base-comparability rule, **drops `r_at_wall` as structurally unfireable and says so** — attempt 8
proved `uft` does not cover this fault path, so carrying the counter open is dishonest.  The
decision is registered here as a choice for the build, not left to be improvised.

## 7. The session

### 7.1 The design

**Localization, not distribution.**  Round 9 is built to *catch and dissect* events, not to
measure their rate — the N-boot distribution is a separate, user-extendable protocol (§8.3).  So
the session front-loads the arms that latch most readily and reads each latch to the bone.

```text
  boot   1     2     3     4     5     6     7     8
  arm    I     II    I     II    I     II    I     II
  temp   W     C     C     W     W     C     C     W
```

Arm I (`ucv`) latches on **any** paired fold disagreement — attempt 8's boot 3 alone had four —
so it does not need the rare wall; it should produce a decisive R1/R2/R3 within a few boots.  Arm
II (`ucm`) latches on **any** A→C flip and localizes it.  Warm/cold is kept balanced against the
arm (att7 §10's stratification was sound); it is **not** a warm/cold experiment.

**Success criterion, registered:** at least one frozen pair on Arm I (→ R1/R2/R3 called) and at
least one localized flip on Arm II (→ R4/R5/R6/R7 called).  If eight boots yield neither, the arms
are read for inertness and the session reports "no event caught" rather than inventing one — a
quiet boot is one draw from a perturbed distribution (`…ATT7-UCP…` §10, not repealed).

### 7.2 The plan

1. **Eight scored boots minimum**, each from a **fresh gated copy** of the work root, in the order
   of §7.1, starting Arm I warm.
2. **Fast tier on every boot**: `swa` first, then the `ucp`/`ucv`(or `ucm`) block including the new
   counters, then the killer `ucp_sent0` read FIRST of that block, then `uft`/`kvd`/`kvfar`, then
   the outcome class, then one thermal and one rail sample.
3. **The frozen pair is read in full on the first boot that latches on each arm** — 804 bytes each
   side for Arm I; the four-point folds plus both endpoint frames for Arm II.  That is the round's
   most expensive read and it is the one R1–R7 depend on.
4. **Any boot whose wall address is not `4AFC0008` reads the full sixteen `u_ar0` longwords first**
   (attempt 7's still-owed protocol fix).
5. **Every boot is scored.  No boot is re-run to green.**  Mechanical non-boots discarded only under
   attempt 5's three-proof rule; firmware-side aborts discarded on their own ground and recorded.
6. **HDMI first**: check `/api/streamer/state` **before** the box is powered; a 404 a fourth time
   makes `putbuf` the planned primary console from the start (`…ATT7-RESULTS…` §11).
7. **The four `…PLATFORM-LC060-Z3660…` §4 readbacks ride every result row**: Clock index +
   PCLK/BCLK, `pcr_boot`, `CACR`, and the load base.  Especially the clock line — the assessment
   turns on which clock the boots ran at.

**Registered as deliberately not in the plan:** no `default_timings` change (§8, a user gate,
fetched read-only as a restore witness); no clock-index change; no card-side change of any kind;
no cure; and the canary (Arm III) only if the session elects the base change.

## 8. The DESIGNED — not enabled — physical-parameter experiment

This is the gold-standard marginality test, the experiment the electrical assessment §5.4 names as
the one that *calls* the question.  It is a **card-side change and a standing user gate**; it is
specified here in full so that when the user says go, it runs from a design rather than an
improvisation, and it is **not run and not enabled by this round.**

### 8.1 The de-rated `default_timings` A/B

The card's `1:/timings/default_timings.txt` sets, per clock index, the DDR/interface phases and
dividers (`pclk.phase`, `clken.phase`, `bclk.phase`, `cpuclk.phase`, `clk90.phase`, and the five
dividers).  The standing session runs **Clock index 0** (`PCLK 50`, `BCLK 25`, `AXICLK 100`).

* **Arm A (standing):** the file exactly as found — the restore witness (`cfg.default_timings.txt`
  hashed before and after every session; never press boot-menu `G`, which reverts it).
* **Arm B (de-rated):** the **same** clock frequencies, with the interface **phase margins
  relaxed** by a conservative step at index 0 — nudging `bclk.phase` / `cpuclk.phase` / `clk90.phase`
  toward the centre of their valid window so the setup/hold margin on the DDR/interface capture
  widens.  Only the phase fields change; the multipliers and dividers (hence the frequencies) do
  **not**, so this is a pure timing-margin A/B with the clock fixed.

**Protocol:** the N-boot distribution (§8.3) on each arm, scoring **only** the outcome class and the
per-*restore* flip rate (att7 §10's exposure fix) plus the four clock readbacks.  **The prediction
that decides it:** if the corruption rate falls (toward zero) on the de-rated arm while the software
is byte-identical, the cause is timing-marginal — a result no software mechanism can produce.  If
the rate is unchanged across a meaningful margin change, the DRAM/interface-timing arm is
disfavoured and attention moves to the AXI/fabric crossing or the cache.

### 8.2 The clock / AXICLK sweep, and its confound

The N-boot protocol at the standing index and at one step that changes the fabric margin.
**Confound, registered:** raising the clock index raises `AXICLK` **and** `PCLK` together (index up
also overclocks the CPU), so a clean AXICLK-only sweep requires editing the timing table's divider
fields to move `AXICLK` while holding `PCLK` — whose firmware semantics must be confirmed read-only
first.  Absent that, the index sweep is a *coupled* CPU+fabric change and is read only as "does any
clock change move the rate", not as an AXICLK-isolated result.  Lower-margin/overclock indices
(105–120) overclock the motherboard and are **not** a "try faster" option (`…PLATFORM-LC060-Z3660…`
§2.4).

### 8.3 The N-boot distribution protocol (prerequisite for §8.1/§8.2)

≥10 boots of one image from one gated disk, scoring only the outcome class and the per-restore
rate — nothing else, so a boot costs minutes not a window.  Paired with an explicit censoring rule
for boots that stop early (att7 §10: censoring at both ends is what destroyed the warm/cold
comparison).  A software race gives proportions stable across sessions; a marginality gives
proportions that move with the physical parameter of §8.1/§8.2.

### 8.4 Hygiene for the gated experiment

Every arm restores `default_timings.txt` **byte-exact** to as-found and re-hashes it (start and
end); never presses boot-menu `G`; carries the four clock readbacks on every row; and aborts to the
standing thermal policy.  A card left on Arm B is a card running a deliberately de-rated bus — the
restore is not optional.
