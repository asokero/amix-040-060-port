# Real-hardware acceptance: `68060-260812-06` — the pre-swap 68060 run

**Machine:** Amiga 3000, 68060 @ 66 MHz, AMIX SVR4 2.1c, `solon` / 10.0.10.10
**Date:** 2026-08-12
**Image:** `build/unix-040`, build id `68040-260812-06`, booted with `unix_boot040` after SetPatch
**Previous 68060 baseline:** `68060-260812-02` (`REALHW-ISSUE43-ACCEPTANCE-260812.md`)

## Why this run happened before the card swap, and not after

`-06` carries two units that `-02` does not: ISSUE-42's write-back denial propagation and the
follow-up audit's corrections. ISSUE-42 is a **68040** defect and its acceptance needs the A3640.
But one measurement can only be taken while the 68060 is still in the machine, and the swap closes
that window:

> the ISSUE-42 unit is gated on the format-7 access-error frame, which only a 68040 produces —
> so on 68060 **silicon** every one of its counters must read zero.

The emulator said so. Silicon is a different claim, and it is now taken.

## 2. The measurement this run existed for: the CPU gate, on silicon

Every counter in the ISSUE-42 block, after a full boot and the entire test set:

```
  wbf_magic       57424621        wbf_prop_on     1      wbf_sup_fatal   1
  wbf_own_cookie         0        <- the u_nofault landing pad was never armed
  wbf_slot               0        <- no write-back replay ever ran
  wbf_fail_n             0        wbf_alien_n     0      wbf_swallow_n   0
  ... every remaining counter in the block: 0
```

The format-7 gate holds on real 68060 silicon. Nothing in the ISSUE-42 unit executes on this CPU,
which is what makes it safe to carry in the dual-CPU image.

## 5. What this run does and does not establish

**Does:** `-06` is accepted on 68060 hardware. The ISSUE-42 unit is proven inert on that CPU by
measurement rather than by reading its gate. ISSUE-43 and ISSUE-44 hold on the new build.

**Does not:** anything about ISSUE-42 itself. Its acceptance is a 68040 question and remains owed;
the emulated 040 exercises only WB2/WB3 because the emulators never set WB1S valid, so the WB1 path
and its ISSUE-11 realignment have still never executed anywhere. That is the first item of
`archive/NEXT-040-SESSION-RUNLIST.md` and the reason for the card swap.

After the swap and a 68040 acceptance run, `-06` becomes the first image in this project accepted
on **both** silicon.
