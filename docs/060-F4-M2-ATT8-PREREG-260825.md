2026-08-25.  Follows `docs/060-F4-M2-ATT7-RESULTS-260825.md` and scores nothing that document
already scored.

**The honest sequence.**  §2's readings and §3's questions come from attempt 7's metal record
and from **static** work on `build/unix-060-f7vsu-CARD1-ced0s1` — the artifact attempt 7 booted
— both of which are written down in the results document committed before this one.  **No

**And one premise of round 7 is superseded by round 7's own data, so it is stated first.**  The
bracket was aimed at the register file, on the reading that a `ucontext` round trip had lost

unfireable from the day it was written.  What the bracket *did* find is a one-directional
bit-set inside a 784-byte field that nothing writes.  §4 therefore re-aims one hop again, and

## 2. Two facts this round is built on, and where they came from

Both are static readings of the artifact that booted, recorded in `…ATT7-RESULTS…` §7 before
this document, and an instrument built on a wrong premise measures nothing.

* **The layout.**  `savecontext` writes `uc_flags` / `uc_link` / `uc_sigmask` / `uc_stack`,
  then `prgetregs → ucp+0x24`, then `prgetfpregs → ucp+0x6C` **only if `prhasfp()`**, then
  `prgetstate → ucp+0xD8`, then `prgetfpstate → ucp+0x134` **only if `prhasfp()`**, then
  `stampsum(ucp+216, 200)` and `~sum` at `ucp+0x3F8`.  `prgetstate` copies exactly
  `framesz[format]` bytes; the table reads `8 8 12 0 16 0 0 60 0 20 32 92 0 0 0 0`.  On a
  68060 access-error frame that is 16 bytes.  **`savecontext` clears bit 3 of `uc_flags` when
  the part has no FPU** — a gate the object carries about itself, and §4.3 uses it.
* **The consumer of the field.**  `prsetstate` takes the frame format from bits 12–15 of the
  **user-supplied** `mc_state[1]` and uses `framesz[]` of it to size a `bcopy` into the pcb.
  `framesz[5] = framesz[6] = framesz[12] = 0`, so setting bit 12, 13 or 15 in a legitimate
  format-4 nibble makes that `bcopy` copy **nothing** and the process resume on a stale pcb
  frame.  A register file that is a stale mixture is the shape of the wall.  **Registered as a
  bridge with a killer (§5 row R3/R4), not as a mechanism**: every flip measured so far is at
  index 12 or above, never at index 1.

## 4. The instruments

Two arms.  **Arm I extends `ucp` inside its existing two hook points and adds no new hook
site.**  Arm II is one `bzero` in the same wrapper, and it is proposed as an **instrument, not
a cure** — §6 says why the cure reading is wrong.

### 4.1 Arm I — `ucp2`: a second fold, a histogram, an evidence slot, two counters

1. **A rotating fold, computed in the same pass as the plain one.**  `acc = rol(acc,1) ^ word`
   is position-weighted, so two longwords flipping the same bit no longer cancel.  One extra
   instruction per longword and one extra accumulator; **no second pass over the 804 bytes.**
   * **Its save-time value goes in the shadow slot's metadata, never in the object.**  The
     object's bytes are `copyout`'d to userland and folded by stock; adding a field to them
     would change what the stock guard sees.  The slot already carries four metadata
     longwords; this is a fifth.
   * `ucp_rot_bad_n` counts restores where the rotating folds disagree **while the plain fold
     passed** — the population stock cannot see.  `ucp_rot_n` counts the restores where the
     comparison was possible at all (a stamp hit), so the counter has a denominator.
2. **`ucp_fmt_h0..ucp_fmt_h15`** — sixteen counters, incremented at `restorecontext` entry by
   `(mc_state[1] >> 12) & 15`.  Plus `ucp_fmt_bad_n` for nibbles that are neither 0 nor 4, and
   a one-shot latch of the first such frame: the nibble, `mc_state[0..3]`, the `ucp`, the
   sequence number.  **This is the only direct test of §2's bridge.**
3. **`ucpev` — a fifth slot, 820 bytes, outside the ring.**  On the first event with a
   difference, copy the whole 804-byte **restore-side** region into it.  The save-side copy is
   already in the ring and both survive to read time, so one boot then yields a complete
   longword-by-longword diff instead of twelve triples.  This is what R5 needs and there is no
   cheaper way to get it: the live buffer is a kernel stack address that is gone by the time
   an operator reads anything.
4. **`ucp_r_at_wall` / `ucp_s_at_wall`** — `ucp_r_n` and `ucp_save_n` latched at the moment
   `uft_have` is first seen non-zero.  The freeze test already runs there for `ucp_ms_lock`;
   these are two stores beside it.

**Registered cost, and it is not small.**  `ucp` already folds 201 longwords per save and per
restore and copies 804 bytes per save.  Arm I adds one instruction per longword on both sides,
a four-slot ring lookup on **every** restore rather than only bad ones, and one 804-byte copy
once per boot.  The ring lookup is the item to watch: four compares against a 32-bit key,
~190,000 times.  **A boot in which the refusal does not occur still cannot be read as "the
defect went away"** — `…ATT7-UCP…` §10 is not repealed and this arm perturbs the same path
harder.

### 4.2 Arm II — `ucz`: zero the field that nothing writes

One `bzero(ucp+0xD8+16, 784)` in the `savecontext` wrapper, **before** our fold and before
anything reads the object, so the stamp stock computes already covers zeros.

**Three gates, and each of them is a way this arm can be wrong:**

* **It must not run on a part with an FPU.**  On such a part `prgetfpstate` writes from
  `mc_state[23]` onward and zeroing after `savecontext` returns would destroy the saved FP
  state.  The gate is read out of the object itself: **zero only when `uc_flags & 8` is
  clear**, which is exactly what `savecontext` leaves when `prhasfp()` returned zero.  So the
  arm is inert on Rig B **by construction**, and that inertness is a bench row rather than a
  hope.
* **It must not run on a frame format it does not understand.**  Zeroing from `mc_state[4]` is
  safe for format 0 (8 bytes written) and format 4 (16 bytes written) and for nothing else —
  formats 7, 9, 10 and 11 write up to 92 bytes.  A 68060 generates neither, but the arm
  **checks rather than assumes**: if `(mc_state[1] >> 12) & 15` is not 0 or 4 it declines, and
  `ucp_z_skip_n` counts the declines.
* **It must be shown to have worked.**  `ucp_z_n` counts the frames zeroed, and the shadow
  ring is read on the bench to confirm `mc_state[4..199]` really is all zero in a slot.

**Why it is an instrument and not a cure.**  Over a zeroed field every source nibble is 0, so
**every bit the mechanism sets is visible** instead of only the ones the stale data happened to
leave clear.  One latching boot then answers Q3 outright.  It also closes a kernel-memory
disclosure that is real on its own merits (§6).  What it does **not** do is stop the failure:
a flip of `00000000` to `00002000` breaks the fold exactly as before.

## 6. The cure question, answered before anyone is tempted

`…ATT7-RESULTS…` §7.3 makes a cure look cheap.  It is not, and the reason is written down now
rather than after a boot.

**The leak is a real defect and it is separable from the corruption.**  784 bytes of supervisor
stack — kernel text addresses, kernel data pointers, saved frame-pointer chains, old exception
frames — reach a user stack on every signal delivery.  It is stock code on stock paths and it
should be fixed on its own merits.  **It is not the same thing as the bit-set**, and fixing it
does not fix the boot.

| candidate | closes the disclosure | stops the `SIGKILL` | keeps the detector |
|---|---|---|---|
| **C1** zero the unwritten field at save | **yes** | **no** — `00000000 → 00002000` still breaks the fold | **yes** |
| **C2** fold only the written region, at both ends | no | yes | **no** — and it hides real corruption in bytes we have not proven are always dead |
| C1 + C2 | yes | yes | no |
| C0 do neither yet | no | no | yes |

**None of them touches the bit-set, which is the actual defect.**  So there is no cure on the
table, the cheap one is not a cure, and C1's real value is that it is **Arm II** — the
de-confounding instrument of §4.2.

**What one more metal boot must show before any cure is implemented**, and both are rows of
this round:

1. **R6/R7/R8 — value-keyed or address-keyed.**  C1 changes the data the mechanism sees.  If
   the flip is address-keyed, C1 changes nothing about the failure and is a disclosure fix
   only.  Implementing it as a "cure" before this is known would be implementing it on a guess.
2. **R1/R2 — is there an invisible population.**  If R2 fires, C2 is not a trade of "detection
   for survival" but a removal of the only visibility this campaign has into a phenomenon whose
   size is unknown.  A checksum that already misses most events is not a checksum worth
   shrinking.

**Registered as forbidden this round:** shipping C1 or C2 as a fix, in any artifact of the
round, under any name.  Arm II is a `.data`-gated instrument arm; its `bzero` is behind the
same `ucp_on`-style gate the rest of the unit uses, so the shipping default cannot become a
silent behaviour change.

## 7. The session

### 7.1 The design, and what it deliberately abandons

**Eight scored boots, the arm as the only factor under test.**  Attempt 7's warm/cold
comparison is **not repeated**: `…ATT7-RESULTS…` §10 shows the latch asymmetry was entirely an
exposure artefact and the wall asymmetry was p = 0.486 on n = 4 per arm, needing roughly twenty
boots an arm to mean anything.  Repeating it here would confound the arm with it for no gain.
**It is not abandoned as a question**, only as this round's design; §10 of that document lists
what it would take, and the first item is a fixed exposure rather than a fixed clock.

Warm and cold are still **balanced against the arm** so that neither carried state nor the
thermal ramp can align with it:

```text
  boot   1   2   3   4   5   6   7   8
  arm    I   II  I   II  I   II  I   II
  temp   W   C   C   W   W   C   C   W
```

Arm I draws W, C, W, C; Arm II draws C, W, C, W.  Interleaved, not blocked.

### 7.2 The plan

1. **Eight scored boots minimum**, each from a **fresh gated copy** of the work root, in the
   order of §7.1, starting with Arm I warm.
2. **Fast tier on every boot**: `swa` first (the only block guaranteed to have fired), then the
   `ucp` block including the new counters, then `ucp_fmt_h0..h15`, then the `uft` head with
   `ucp_r_at_wall` beside it, then `kvd_n` / `kvfar_n` / `kvd_split_n`, then the outcome class,
   then one thermal and one rail sample.
3. **Full census on boot 1 and on any boot that fires a row no earlier boot fired.**  A new row
   is worth a window; a repeat is worth a line.
4. **`ucpev` is read in full on the first boot that latches on each arm** — 804 bytes on each
   side.  That is the round's most expensive read and it is the one R6/R7/R8 depend on.
5. **Any boot whose wall address is not `4AFC0008` reads the full sixteen `u_ar0` longwords**
   before anything else.  This is attempt 7's owed protocol fix (boot 2) and it costs no window.
6. **Every boot is scored.  No boot is re-run to green.**  Mechanical non-boots are discarded
   only under attempt 5's rule with the same three independent proofs; a firmware-side abort is
   discarded on its own separate ground and recorded either way.
7. **HDMI first, per `…ATT7-RESULTS…` §11.**  Check `/api/streamer/state` before the box is
   powered.  If it 404s a third time, plan the window around `putbuf` from the start rather
   than discovering it mid-session.

**Registered as deliberately not in the plan:** no `--cache 0` control; no `nullvect` chain; no
card-side change of any kind; no `default_timings` change, which remains an explicit user gate
and is fetched read-only as a restore witness; no third arm.
