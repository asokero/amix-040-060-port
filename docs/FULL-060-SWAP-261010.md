# A full 68060 in place of the 68LC060 on the A4000T's Z3660 — what the kernel does, 2026-10-10

Read from the code and the records only; nothing built or booted for this page. The platform rules
are `ACCEPTANCE.md` §1 (name the class) and `PLATFORM-LC060-Z3660.md` (what that class does not
model). A full 060 on a Z3660 is neither the Mercury (`HW`, local bus, booted under SetPatch) nor
`LC060-Z3660`; its results carry their own tag, e.g. `060-Z3660`.

## 1. Is a hardware FPU detected and used? Yes — the same image, no rebuild.

- `fpuinit` (`src/fpuinit060.s`, default `FPUINIT060=1` in `relink-040.sh`) is the authority. It
  reads PCR, clears bit 1 (`DFP`, FPU disable), writes it back, then probes vector 11 with an FSAVE.
  A full 060 lands in **regime 1**: `fpu_present = 1`, eager FP save/restore on context switch —
  the path accepted on the Mercury (`fpc_save_n 8059 / fpc_rest_n 7647`).
- If the Z3660 extension ROM disabled the FPU (it has a path gated on PCR ID `== $430`,
  `060-F4-M2-PREREG-260824.md:180`), that is regime 2, and step 4 moves it to regime 1. Read
  `fpi_pcr_pre` bit 1 to see what the ROM left.
- **The software FPE does not engage.** `relink-040-fpe.sh` arms the NetBSD emulator only on
  `fpuinit`'s negative answer (`fpu_emul` is set in one place, `src/fpe040.s`); every arm tests
  `fpu_present` first. The bar is `fpe_entry_n == 0` and `fpu_emul == 0` on every FPU-present rig
  (`contracts/FPE-GLUE-DESIGN.md` decision 7, §9). The `fpe_v11_*` census is counted ahead of the
  gates and **is expected to move** — it is not a failure.
- pgrsv and isp060 (opt-in passes on this branch, default on the driver line since r6) do not
  touch FP.

## 2. The FPSP, and what userland will see

- The 060 retires only part of the 68881/2 set in hardware. The rest — `fsin`, `fetox`, `flogn`,
  **`fmovecr`** (how gcc loads `0.0`/`1.0`), packed decimal, unimplemented data types, enabled IEEE
  exceptions — traps to vector 11 and is completed by **Motorola's 060 FPSP**, which is in every
  060 kernel by default (`FPSP060=1`, `build-fpsp060.sh`, `src/fpsp060_glue.s`). Without it those
  died with SIGSYS (`060-FPU-STATE-260807.md`, the pre-FPSP measurement).
- So with the FPU: `fadd/fmul/fdiv/fsqrt` run in silicon, transcendentals and `fmovecr` take one
  trap each into the FPSP (counted in `f60_entry_n`). **Measured 2026-10-11: the stock libm
  issues none of the transcendentals** — `sin`/`exp`/`log` are software polynomials of `fadd`/
  `fmul`/`fdiv`/`fintrz`, all retired by silicon. Its only FPSP opcode is `fmovecr #15` (0.0), on
  some branches of `atan`/`atan2`, `hypot`, `erfc`, `lgamma`, `j0`/`j1` and `pow`; `awk` carries
  three. So awk/libm rows run in silicon, and the FPSP is exercised by the §6 060-only set.
- Userland that behaves differently: none of it should *fail*. What changes is accuracy class —
  FPE results are NetBSD-emulator results, FPSP results are Motorola's (`fp060probe` "7/7 bit-exact,
  0 ulp", `ACCEPTANCE.md` §6). `fsck_ufs`/`mkfs_ufs` print FP in their summaries
  (`PLATFORM-LC060-Z3660.md` §2.1) — a non-issue with an FPU.
- `/usr/bin/cc` (gcc) died on vector 61 on any 060 (`ACCEPTANCE.md` §5); the ISP pass
  (DRIVER-LINE-9) completes those forms, proven on metal 2026-10-11 (gcc itself not re-run).
  `/usr/ccs/bin/cc` stays the safe compiler.

## 3. Mask revision

- Nothing in the port branches on the revision. `pcr_boot` records it; the decisions use `cputype`
  and the vector-11 probe. The Motorola FPSP/ISP packages are revision-independent.
- Known readings: Mercury full 060 `0x04300601` (ID `$0430`, rev 6, `ESS` set by SetPatch);
  this LC060 `0x04310402` (ID `$0431`, rev 4, `ESS` clear). Early-mask errata are not recorded or
  worked around anywhere in this repo. A rev-1 part is untested territory: if it misbehaves, compare
  against the rev-6 Mercury rows before blaming the kernel.
- Native Z3660 boot sets no `ESS` (superscalar dispatch) — nothing in the port writes it. A float
  number from this box is comparable to an AmigaOS-hosted 060 number only with PCR read on both
  sides (`PLATFORM-LC060-Z3660.md` §2.9).

## 4. Re-run after the swap (`ACCEPTANCE.md` §11 order)

1. **Identity**: `uname -m`; `pcr_boot` (expect `$0430`, record the revision byte and `ESS`);
   `fpi_magic`, `fpi_nofpu_n = 0`, `fpi_pcr_post` bit 1 clear, `fpu_present = 1`, `fpu_emul = 0`;
   clock index and PCLK/BCLK (§2.4 of the LC060 page — never press boot-menu `G`).
2. **One FP event**: `awk 'BEGIN{print 1.5*2.5}'` → `3.75`, `fpe_entry_n` still 0, `f60_entry_n`
   moved.
3. **The common battery** (§5, the historical eleven).
4. **The 060-only set** (`ACCEPTANCE.md` §6), first time on a Z3660 — last accepted on the Mercury
   (`REALHW-260812-06-ACCEPTANCE.md`): `fp060probe` 7/7, `ftest060 unimp` and `main`, `fpenab060`
   six classes, `fputest060 fork`, `isp61ea` 7/7. Add the r6 ISP probe set
   (`isp060probe`, outside this tree): DRIVER-LINE-9's one metal boot, run 2026-10-11.
5. **The FPE set**, predictions re-registered: anything that expected the emulator to move now
   expects `fpe_entry_n == 0` with the same user-visible results.
6. **amix-bench float rows**: a new baseline, annotated with `ESS` and the clock index; not
   comparable to the LC060 rows.
7. **An install, then the burst soak** (§7), under the thermal policy: a new part re-characterizes
   its plateau from scratch under the 15-minute cap (`PLATFORM-LC060-Z3660.md` §2.7).
8. **Power cut last.**
