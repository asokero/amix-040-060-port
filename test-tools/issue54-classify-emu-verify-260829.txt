WHAT THIS DOES AND DOES NOT SHOW

Shows: the classification code is inert.  It does not fire on any status the emulator produces,
it does not perturb the driver, the kernel boots and does normal disk I/O, and the block is
where tools/status-facts.sh says it is.

Does not show: anything about ISSUE-54.  Amiberry's SCSI does not produce a phase mismatch, so
0x48/0x49/0x4a never arrive and the measuring half of this instrument has never executed.  That
requires the hardware trigger, and it costs a power cycle and an fsck.

Serial carries the loader only on this bed -- 18 lines, ending at the image checksum.  "Booted"
here means the kernel's own memory reads back correctly over Amiberry IPC and the DMA counters
advance, not that a login prompt was seen on the serial log.
