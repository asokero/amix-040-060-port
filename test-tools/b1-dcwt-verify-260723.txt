What changed (per DTT0-NARROWING-SPEC.md "Decision" -- deliberately minimal)
---------------------------------------------------------------------------
* pstart040.s 'D' step: cinva dc (0xf458) BEFORE the enable (discards DC lines
  inherited from AmigaOS -- the ISSUE-21 config wrapper disables caches WITHOUT
  flushing, so a cpusha here would write stale AmigaOS data over kernel RAM);
  cinva ic kept; CACR immediate 0x00008000 -> 0x80008000 (bit31 DE/EDC + bit15
  IE/EIC, same bits on 040 and 060); both `cacr` and `sup_cacr` data globals get
  the same value (p1..p4int/p6int/nullvect reload sup_cacr per interrupt; p5int
  loads neither -- harmless, values equal); dbg-only serial evidence: after the
  'D' btrace mark, movec %cacr,%d0 read-back printed via btrace_hex.
* haltsys040.s: cpusha dc (0xf478) added after SR=0x2700, BEFORE the TC/TTR
  teardown ("Shutdown ordering" spec item; pure invalidate in B1 WT, mandatory
  push in a future B2 CB build -- one line covers both stages).
* NOTHING else: DTT0 stays 0x003fc060, DTT1 0x807fa060, ITT0 0x003fc000
  (census: TTRs match LOGICAL addresses; high PTE mappings already take leaf CM;
  SRP has no low identity map so DTT0 E=0 would fault the kernel immediately).
  hat_cm_ram stays 0x00 (WT).  No phys-window conversions (census: all D0 paths
  stay NC via DTT0; 040 physically-tagged cache + NC-access matching-line rule
  keeps the low NC alias coherent with high WT aliases; DMA covered by the
  A3091 FROM_DEVICE completion invalidate).
