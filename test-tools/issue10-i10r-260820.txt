WHAT THIS IS.  The emulator-side watch (ISSUE10-SETUPSH-WALL-260819.md section 14)
established the mechanism from OUTSIDE the guest: a user write-class first-touch
fault on a freshly brk'd anon page returns without mapping the page, without zero-
filling it, and without replaying the valid pending write-back the 68040 handed
over -- so the marker store (value _end+1 = 0x800114B5, destination 0x800152A0)
VANISHES, the coalescing walk later reads a NULL where its terminator should be,
follows the NULL to user VA 0, reads the kernel's own ILLEGAL-at-null sentinel
0x4AFC0000, and walls on btst at 0x4AFC0003.  Section 14 could see that the kernel
did nothing; it could not see WHERE inside the kernel.  i10r rides the user fault
path itself -- both ends of the usrxmemflt wrapper -- and latches ONE watched
fault so the swallowing branch is named rather than inferred.  It is armed with a
single kpoke of the address to audit (0x800152A0, the store section 14 measured
vanishing) and write-protects NOTHING: i10g_on and i10w_on stay 0, so the audited
fault is the ordinary one the uninstrumented wall takes.

RESULT: THE BRANCH IS NAMED, AND SECTION 14's "returns as-if-resolved" IS REFINED.
The audited fault is a 68040 format-7 user-data WRITE (fmtvec 0x7008, pre_ssw 0x0401
-> ATC set, RW bit clear = write, TM 1 = user data; pre_sr 0x0008 -> S clear).  The
kernel received EXACTLY the frame the CPU pushed -- pre_w3s 0x81 (valid, size long,
TM 1), pre_w3a 0x800152A0, pre_w3d 0x800114B5, and the post_ copies are identical:
no frame-copy discrepancy, so the emulator's arming is faithful (it matches the
emulator's own WB7 decode of the same fault).  ptest is real and active in this
kernel (ptest040.s) and reports the page ABSENT: pt_pre = pt_post = 0x400 (030-form
I, invalid), mmusr_pre = post = 0 (040 MMUSR R clear), pte_pre = post = 0.  So the
stock classifier takes branch 3 -- the F_INVAL demand path (5aff6) -- which is the
CORRECT classification for an absent page.  It then calls as_fault(F_INVAL, S_WRITE),
and that call FAILS: ret = 0x0B (11 = SIGSEGV), sisig = 0x0B, sicode = 1
(SEGV_MAPERR), siaddr = 0x800152A0, and nothing is mapped or stored (pte_post = 0,
tv_pre = tv_post = 0 -- the marker 0x800114B5 never lands).  Because usrxmemflt_orig
returned nonzero, the wb040 wrapper's `tstl %d4; bnew Lu_done` SKIPS the write-back
replay entirely (wbrep_pre = wbrep_post = 0xC8 = 200, delta 0), so the valid pending
store dec3 = 1 says the frame carried is dropped -- a direct consequence of the
SIGSEGV verdict.  wbfail_d = wbsig_d = x60sig_d = 0, so ret = 11 IS usrxmemflt_orig's
OWN return, not a wrapper substitution.  nest_n = 0, match_n = 1, alien_n = 1 pending
frame accounted; proc 0x4013BE00 is the wall's own sh.  The faulting store's own
registers confirm the source value is correct, not fabricated: r2 (d2) = 0x800114B5
(the marker) and r9 (a1) = 0x800152A0 (the target) -- i.e. `move.l %d2,(%a1)` at
sh's addblok, one instruction before the deferred-write-back PC 0x8000250E.

READING (analysis, not measurement).  Two things this refines in section 14:

  1. Section 14's "no signal is delivered" was the emulator watch's inference from
     memory and frames.  i10r reads the resolver's OWN output and it is a SIGSEGV
     (sisig = 11, SEGV_MAPERR, siaddr = 0x800152A0).  Per wb040.s Lu_siginfo, u_trap
     selects its fault class from infop->si_signo and queues a signal whenever it is
     nonzero; si_signo = 11 here, so this is a REAL, queued SIGSEGV, not a silent
     as-if-resolved return.  That sh nonetheless continues to the later wall in the
     same run means sh SURVIVES the signal (Bourne sh catches memory faults for arena
     growth; the flood's closing "no space" is that same catch-and-retry giving up).
     i10r's hooks end at the wrapper exit and cannot see psig/sendsig or sh's signal
     disposition, so whether "sh sails on" is delivered+caught+resumed or a delivery-
     path defect is the one field this instrument does not capture (see the doc's
     section 16 for the exact next latch).

  2. The store did not "vanish silently into a resolved fault"; it vanished because
     the demand WRITE fault FAILED (as_fault returned an error) and the replay was
     therefore skipped.  The genesis is a segvn/as_fault WRITE-demand-fill failure on
     a first-touch write to a freshly grown anon page -- NOT a segment-table (sdt)
     allocation failure: the fatal page 0x80015000 shares an already-resident leaf
     page-table with the prior arena top 0x80014AA0 (both A=64,B=0 in the 040 walk),
     so no table is allocated at fault time, and the native 040 hat_pteload uses
     hat_ptalloc/page_get, never hat_sdtalloc.  The proof that the page is mappable is
     section 14's own reading: the READ fault five ticks later maps and zero-fills the
     same page.  Only the WRITE variant fails.
