PARSE-SIZE FACTS (blocks B, C, D)

  setup.sh truncated to N KiB, `sh -n` (parse, execute nothing):
     2  4  8 16 32 KiB -> rc=0, clean
    34 KiB              -> rc=0, clean
    36 KiB              -> rc=2, truncation syntax error (parse aborted early)
    38 40 42 44 46 48 64 76 KiB -> "no space", rc=1, with the BUS ERROR flood

  So the wall sits between 34 and 38 KiB of setup.sh text.  It is not raw size: a
  synthetic 64 KiB script built by concatenating the SAME syntactically-complete 4 KiB
  chunk 16 times parses clean at every step from 8 to 64 KiB (block C), because each
  repeat redefines rather than grows the parse tree.  The wall tracks the size of the
  unique parse tree, i.e. how far sh's arena has to grow.

  install.sh (118500 bytes) fails identically under `sh -n`, so the wall is not a
  property of setup.sh.
